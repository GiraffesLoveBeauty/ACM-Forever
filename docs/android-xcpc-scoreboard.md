## 页面范围

用户明确：1.0.2 及本轮所说的排名优化均指社团题单的完成情况。1.0.2 曾误改普通排行榜；本轮将 `MainActivity.java` 精确恢复为 `140bf49` 前的源码，恢复原横幅、文字筛选、头像与统计布局。紧凑布局和新增统计仅作用于管理员题单计分板，不重写已发布的 1.0.2 Tag 或附件。

题单页面的筛选与排序默认收起，展开后仍可按姓名、QQ、身份和完成情况筛选。表格两侧固定成员和成绩，中间题目列先随可用宽度缩小，最窄 42dp，再横向滚动。成员列为 96–124dp，成绩列为 64–84dp；默认行高 58dp，大字体随字体比例增高。统一细边框和交替行底色，不为每个格子使用大圆角卡片。

用户名下方显示真实姓名；长文字在格子里省略，点击题目后显示完整成员、题目、状态与时间。真实姓名仅来自管理员接口，普通排行榜与普通成员不新增访问入口。

## 过题数与总用时

- `AC` 表示已有通过证据，下一行显示自题单开始至本题首次已核验 AC 的分钟数；历史已通过显示“历史”。`?` 表示待核验，`—` 表示没有通过证据。
- 页面只显示**总用时**，不设置错误提交计数、加罚或对应的缺失提示。总用时是每道有准确时间的首次已核验 AC 用时分别向下取整后相加，例如 10 分钟和 25 分钟合计 35 分钟。
- 开始前及缺少实际时间的历史 AC 计入过题数，不计入总用时；缺少时间不能显示 1970 年，也不能编造提交时间。时间以北京时间显示到秒，仅代表本题单采用的首次已核验证据。
- 默认不排名。开启排名后使用 `order=xcpc`：全体筛选后的成员先按通过题数降序，再按总用时升序，完全相同则并列（1、1、3）；服务器排好后才分页。原 `order=completed` 的纯完成数量排序保留兼容旧客户端，不修改其并列规则。
- 每题下方增加“总 AC 人数”统计行，统计整份题单的所有接收成员，每人每题最多计一次，不随分页、姓名/身份/完成筛选缩小。统计列随题目列一起横滑，两侧固定模块保持对齐。

## 接口和性能

```text
GET /api/admin/training-tasks/{id}/progress
    ?page=1&page_size=20&search=&identity=&status=&order=none|completed|xcpc&view=xcpc
```

原响应 `summary/items/total/order` 保留。`scoreboard` 的主要字段：

| 字段 | 含义 |
| --- | --- |
| `columns[].accepted_count` | 本题在整份题单中的 AC 人数，新字段 |
| `participant_count` | 整份题单的接收成员数，新字段 |
| `totals_scope=task` | 确认汇总覆盖整份题单，新字段 |
| `rows[].name/real_name/rank` | 当前页成员与服务端全局名次 |
| `rows[].cells[].state/accepted_at` | 与题目列对应的核验状态、可用时的首次 AC 秒级时间戳 |
| `rows[].penalty_minutes` | 保留旧字段名，App 显示为总用时；不增加错误提交加罚 |

`order=xcpc` 必须与 `view=xcpc` 一起使用。无筛选结果时仍返回整份题单的真实汇总；普通成员访问本管理接口继续返回 403。旧客户端可忽略加法字段；旧服务器缺少汇总时显示“未提供”，不能对当前页求和冒充全题单人数。旧服务器不支持新排序时明确提示，不在 App 内对当前页重排。

全量汇总与排序共用一次题单证据批量查询，并复用既有 `problem_progress` 的状态判定；不逐成员查询、不补抓 OJ、不改证据或触发写入。只有显示当前页成员时才返回姓名和题目格子。点题及展开筛选使用当前数据，不额外请求或刷新页面。
