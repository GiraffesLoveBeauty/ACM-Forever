# 题目难度与算法标签统一配色（#102）

关联：[Issue #102](https://github.com/GiraffesLoveBeauty/ACM-Forever/issues/102)。基线：`main a1edf05`；实现分支：`codex/issue-102-problem-colors`。

本次统一网页中的题目元信息：难度保留数值与来源，算法标签保留名称、筛选键及数据来源，通过共享组件稳定着色。实现只消费现有题目数据，不增加配色接口或逐题分类请求。

## 难度语义

Codeforces 使用题目原始 rating，采用以下区间。颜色不能替代数值，也不将选手称号作为题目等级。

| CF rating | 色系 |
| --- | --- |
| 有效正数且小于 1200 | 灰色 |
| 1200–1399 | 绿色 |
| 1400–1599 | 青色 |
| 1600–1899 | 蓝色 |
| 1900–2099 | 紫色 |
| 2100–2399 | 橙色 |
| 2400 及以上 | 红色 |

- 缺失、空字符串、布尔值、非法数值及无效 CF rating 使用中性“难度未知”，避免把空值转换成零分。
- AtCoder 保留自己的配色区间与来源说明；AtCoder Problems 的估计难度与比赛配分分别表达，不套用 CF rating。没有可确认评分来源的数据保持中性，不猜测换算关系。
- 洛谷继续使用 `LuoguBadges` 展示原生难度名称、等级与颜色，算法标签继续保留原生分类。洛谷原生标签不通过 CF/中文算法别名表重新分类。
- 洛谷旧推荐/过题记录只有中文难度文本且未关联原生分类时，保留原值并标记为历史难度，不猜测等级 ID；缺失或非法数值保持未知。
- 其他平台的原始难度保持平台语义和数值，不自动视为 CF rating。
- 成员个人 rating、账号身份、权限徽标、AC/尝试状态不属于本次题目难度映射范围。

成员题库、后台数据库列表和比赛进度接口附带本地已保存的 AtCoder `difficulty_source`、`difficulty_raw`、`difficulty_is_experimental` 白名单字段，使同一道题在不同页面使用相同评分证据。列表只有在展示值与该题已保存的本地模型值一致时才附带模型来源；历史比赛配分与模型值不一致时继续使用中性样式。此扩展不发起网络分类请求、不修改难度数值，也不需要数据迁移。

## 算法标签

共享映射集中维护 CF 英文标签和已有中文算法别名。同一标签在列表排序、分页、刷新及页面切换后保持相同类别，新增或未识别标签使用中性色。

| 类别 | 示例 | 色系 |
| --- | --- | --- |
| 基础与策略 | implementation、sortings、binary search、greedy、constructive algorithms、暴力枚举 | 橙色 |
| 搜索与图论 | dfs and similar、graphs、trees、shortest paths、flows、BFS | 蓝色 |
| 动态规划 | dp、背包、区间 DP、状态压缩 DP | 紫色 |
| 数据结构 | data structures、dsu、树状数组、线段树、堆 | 青色 |
| 数学与数论 | math、number theory、combinatorics、probabilities | 金黄色 |
| 字符串 | strings、string suffix structures、KMP、哈希 | 绿色 |
| 计算几何 | geometry、凸包 | 粉色 |
| 其他/尚未归类 | 新标签、无法识别的标签 | 中性灰色 |

标签使用小圆角框、细边框和浅背景，允许换行；过长的单个标签可以断行。归一化兼容现有字符串、JSON 数组与标签对象，去空、去重，不修改原始业务存储。

交互与来源保持原有约定：

- 原站标签、AI/规则映射标签、人工添加与复核信息继续分别显示来源。
- 题库已有的可点击筛选标签继续使用原始标签 ID；纯展示标签不增加按钮或无效点击。
- 训练和管理选题原本隐藏算法标签的情形继续隐藏，不因共享组件而提前泄露标签。
- 洛谷原生分类使用源站字典，不以颜色相近为由合并跨平台标签。

## 组件与覆盖清单

| 文件/模块 | 作用 |
| --- | --- |
| `feat/web/src/lib/problem-presentation.js` | 数值校验、平台难度展示、算法类别映射与标签归一化 |
| `feat/web/src/components/ProblemDifficulty.vue` | 跨页面题目难度展示 |

| `feat/web/src/components/ProblemTags.vue` | 标签集合与空状态 |
| `feat/web/src/problem-presentation.css` | 限定在题目元信息组件内的配色、边框与换行样式 |
| 成员题库、题面、比赛做题进度 | 同一题目难度与标签统一；保留返回位置、分页、筛选和收藏 |
| 个人中心、训练推荐、挑战/训练记录、训练任务题单 | 统一题目元信息；保持完成状态和标签隐藏规则 |
| CF 练习选题、近期做题、候选题、成员做题详情 | 统一管理选题与记录里的题目元信息 |
| 后台题库数据库浏览 | 难度与标签使用同一展示规则，洛谷使用原生分类 |
| 标签管理与二次处理结果 | 保留自动/人工/原站来源及编辑交互，统一算法标签外观 |

主题适配使用独立语义类，不全局覆盖 `.chip`。难度与类别有不同明度版本，保留数值、类别名称或标签文字；默认深浅主题和自定义主题均需检查文字、边框及操作按钮是否清晰可用。

### 2026-11-16 浏览器与视觉检查

使用真实 `main a1edf05` 源码快照作为修改前页面，并分别启动修改前、修改后的本地 Vite 页面。两边使用相同合成 API 响应，未连接真实成员账号或生产服务。

- 五个主要页面：成员题库、题目详情、比赛做题进度、管理员题库表格、CF 练习近期题目。
- 三种配色：默认浅色、默认深色、代表性粉色自定义配色；两种宽度：1440px 和 390px，共 30 组当前页面检查。
- 30 组均无页面脚本错误和页面级横向溢出。比赛进度及管理宽表保留自己的横向滚动区。
- 对当前渲染的难度徽标和算法标签测量文字与自身背景的对比度：浅色及本次自定义配色最低 4.78:1，深色最低 6.91:1；该结果不扩展为所有页面文字或任意用户配色的验收。
- 压力样例包含多标签、缺失难度、未知标签和很长的单个标签。长标签按容器宽度断行；比赛表格行高可随内容增长，标签不覆盖相邻题目或操作按钮。
- 另完成八个页面/行为烟测：可点击算法标签保留原始筛选 ID，题面返回保留筛选，比赛单元格打开题面后可返回比赛视图；AtCoder 明确来源的估计难度使用自己的色阶，未标注来源的原始值保持中性；洛谷仍展示原生等级及标签。
- 已目检桌面题库、深色题面、深色比赛进度、手机自定义题库及管理表格截图。修改前共 10 张截图，当前主要矩阵共 30 张，来源/交互烟测另有 8 张。

本地结果文件位于忽略目录 `data/issue-102-preview/`：`before-screens`、`after-screens`、`after-smoke-screens`。各目录的 `results.json` 记录合成场景、页面错误、宽度、实际颜色及截图文件名；这些文件和临时预览源码不纳入 Git 提交。

浏览器验收使用临时合成数据库或合成响应，不对生产账号和题库执行写操作。日志、预览和截图留在忽略目录或仓库外，不作为源码提交。本次不涉及数据库迁移。

后端专项还覆盖损坏分类元数据的降级：详情保留已有题目内容，将难度来源标记为未知；列表、比赛进度与详情不公开整个 `metadata_json`。后端测试使用模拟网络与临时 SQLite，不是生产数据验收。
