# 帖子修改与重新投稿

作者从帖子「修改帖子」或个人中心的投稿进度进入编辑；审核未通过的帖子显示「修改后重新投稿」。编辑使用现有草稿编辑器、自动保存、导入、封面与正文图片。每篇原帖至多存在一份修改草稿，多次进入会继续该草稿，不覆盖未提交修改。

保存草稿不改变原帖。提交时沿用原帖 ID，把新内容置为待审核，原帖暂时退出公开列表；审核通过后恢复公开，评论、点赞、收藏及原创建时间保留。退回原因和替换前的文字源文保存于作者可见的修改记录；历史附件不作永久归档，也不通过历史记录开放私有图片。

原帖内容或审核状态在编辑期间发生变化时，提交返回 409，草稿保留。请先复制需要保留的输入，在投稿进度核对最新结果，再删除旧修改草稿并重新进入编辑。已删除帖子不能重投。管理员提交审核时携带列表返回的 `content_version`；版本变化返回 409，需刷新后重新审核。旧 API 客户端仅在原始第 1 版时可省略版本，修订版必须携带。

## 接口

- `POST /api/forum/mine/posts/<id>/edit`：登录 Cookie + CSRF；仅作者，创建返回 201，继续已有草稿返回 200，响应 `id` 为草稿 ID。
- `GET /api/forum/drafts/<id>`：增加 `source_post_id`、`source_version`、`edit_version`；普通新帖草稿为空。
- `POST /api/forum/drafts/<id>/submit`：修改草稿携带 `edit_version`，成功返回原帖 ID，仍为 201；提交与资源引用、历史快照在一个写事务中完成。
- `GET /api/forum/mine/posts/<id>`：增加 `content_version` 和最近 50 个文字历史快照。仅作者可读，`private, no-store`；公开详情不返回历史。
- `POST /api/forum/moderation/posts/<id>`：审核请求增加 `content_version`，由待审核列表获得。不得使用旧版本审核新正文。

初始化以增量方式增加帖子版本、草稿来源列与 `forum_post_history`，旧数据从第 1 版起。发布前按现有流程备份数据库及图片；代码回退保留新增表和列，不删除历史。与评论 Markdown、Wiki 加速 PR 独立。

## 验证

后端论坛相关 35 项（新增修订专项 8 项）、前端 176 项、Edge 桌面/手机浏览器 8 项均通过，生产构建通过。覆盖权限与 CSRF、重复进入草稿、原帖 ID/互动保留、退回原因归档、重新审核、旧审核版本冲突、编辑期间审核/删除冲突、共享图片私有访问、无效图片事务回滚，以及原投稿流程。测试使用临时合成数据库。

修改草稿的保存和提交必须携带读取/保存响应中的最新 `edit_version`。同账号的两个标签页发生竞争时返回 409，拒绝覆盖或提交另一标签页更新后的草稿；输入保留在编辑器和现有本地恢复副本中。普通新帖草稿兼容旧客户端，提供版本参数时同样校验。
