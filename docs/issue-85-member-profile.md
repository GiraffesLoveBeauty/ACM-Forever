# Issue #85：成员资料筛选与可恢复编辑

状态：已实现，草稿 PR #103 关联 `Closes #85`，待跨人评审。设计基线为 main `1c89408`，遵循需求方 2026-11-05 确认的成员资料方案。

## 范围

成员资料提供关键词、学校及身份组合筛选，列表独立展示真实姓名、昵称、学校、身份、Web 权限和四个平台账号。QQ 与权限只读；校 OJ 保留原详情维护入口。

新增按成员的编辑快照及严格 PATCH：白名单、资料指纹、账号代际和事务内操作者校验；OJ 沿用格式、唯一性、确认、版本和清理规则。数据库无新增迁移。账号管理、导入、注销及密码流程保持原有行为。

列表支持多行编辑、有界并发保存、逐行错误、三方冲突核对。草稿仅在当前浏览器按管理员作用域、成员代际及编辑副本隔离保存，恢复需重新核验服务端；成功仅清理对应版本，网络不确定先对账。

## 实现与界限

| 部分 | 实际处理 |
| --- | --- |
| 查询 | 相同 read transaction 计算总数/分页；真实姓名搜索，学校/身份精确 AND，全量去重候选，越界页回退 |
| 更新 | 仅显式白名单；资料 SHA-256 指纹与 epoch；最终写事务内复核权限，写后快照在事务内生成 |
| OJ | 复用现有规范化、唯一约束、原绑定/版本确认、清理和审计；只有实际变化的平台触发处理 |
| 列表 | 八项编辑字段、QQ/权限只读、明确空值、局部横向滚动；详情保留校 OJ、统计和最近 AC |
| 身份 | 全量候选、待保存名称复用、新建验证；未确认输入也可恢复；Esc、焦点限制与返回 |
| 草稿 | localStorage 最小 schema；非认证作用域、代际和独立副本；输入即时保存，明确恢复，条件失败不虚报保障 |
| 保存 | 最多 3 个请求并发；部分失败保留，成功只清理对应版本；授权失效停止排队，超时先对账 |
| 冲突 | 显示原始/服务端/本地三方值，逐字段选择后仍以新指纹确认保存，换代际不可应用 |

`draft_scope` 由服务端按经验证的 QQ/epoch 或配置的 legacy 管理员身份及部署命名空间派生，不能作为认证凭证。旧式共享管理员只能隔离到同一账号。草稿不跨设备同步，不是加密存储，不保证浏览器清理后的恢复；不会因时间到期静默删除。

资料指纹检测快照内容变化，不记录每次历史变动。未采用新指纹协议的旧 PUT/机器人调用仍保持原有行为，新 PATCH 可以发现它们已经造成的变化；本次未宣称旧入口获得双向并发保护。统计不参与指纹；隐藏的校 OJ 值与版本参与指纹但不允许由列表 PATCH 修改。

## 2026-11-05 审核修复

针对审核版本 `29a78ff` 的三项队列问题补充正式反例并修复：

- P1：验证、OJ 影响确认和发送使用同一份独立提交快照，固定 payload、资料指纹、修订及草稿标识。排队期间后来输入的 OJ 不进入已确认的批次；成功后作为后续草稿保留，再次保存重新确认。
- P2：worker 发送前复核原草稿对象及标识是否仍有效；放弃尚未发送的等待行即取消排队请求，并显示取消数量。同 QQ 重新编辑产生的草稿不会恢复旧请求。
- P2：成功返回后用服务端快照更新资料基线，保留提交后输入（包括将字段改回原值、未确认或已应用的身份输入），结束 saving 状态。已经打开的身份抽屉可继续记录后续输入，返回后不锁死整行。

新增 5 项实际 Members 组件反例及 2 项状态回归；新增 2 个真实 Cookie/API 浏览器场景，在桌面和手机分别执行。原三项反例在修复前全部失败、修复后全部通过。草稿/组件专项现 34 项、前端全量 288 项、Edge 桌面/手机完整浏览器 72 项及生产构建通过；完整回归后的队列状态收尾增量，另以最终构建上的成员资料浏览器专项 12 项复验通过。最新线上检查状态见 PR #103，结果写入交付记录。本次仅修改前端、正式回归测试和相关说明，API 契约及数据库不变。
