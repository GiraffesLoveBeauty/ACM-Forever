状态：源码评审候选。基于已发布 0.2.28（main `c2054e5`），版本号 `0.2.29` / `43`。本轮通过 PR 提交，尚未合并、创建 Tag 或发布。

## 页面与权限

| 场景 | 本轮行为 | 读取接口 |
| --- | --- | --- |
| 管理员打开社团题单 | 默认全部题单，包含其他管理员创建和未分发给自己的题单；支持切回我的题单、状态筛选和分页 | `/api/admin/training-tasks`、`/{id}`；管理读取前重新验证会话 |
| 普通成员题单、我的训练安排 | 仍只显示本人收到的任务；不开放管理数据 | `/api/me/training-tasks`、`/{id}` |
| 全部题单详情 | 展示汇总、说明、题目及管理入口；不向本人进度刷新接口提交未分配的任务 | 管理操作经原可选管理模块及服务端权限检查 |
| 管理首页 | 装饰标题在前，社团题单管理、账号管理及其他入口在后 | 沿用原接口 |
| 论坛 | 首次请求 `page=1&page_size=2`、仅展示两条；兼容服务器最少返回五条，余下先缓存在本页；下滑逐批展示，用完再取下一服务端页，保留手动继续加载入口 | 仍通过 `api.publicPostsPath` 选择支持公开成员ID的接口；按响应的实际 `page_size` 计算服务端页码 |
| 缓存与返回 | 同一页的缓存、实时响应替换同一位置，按帖子ID去重；返回恢复已加载范围和滚动位置 | 不在 instance state 存账号凭据或整份帖子正文 |
| 主动下拉刷新 | 论坛回到两条；题库回第一页20条；榜单回第一页并使用用户所选每页数量；筛选保留 | 不把论坛的两条限制应用到题库或榜单 |

没有修改网站、业务后端、数据库、自站配置及延期 1.0.0 渠道。

当前后端 `forum_api.public_posts` 把 `page_size` 限制为5～30，移动端公开帖子接口也复用该实现。因此不能把请求中的2当成服务器实际页大小。本轮客户端兼容现有契约，不改后端，不通过丢弃后三条来伪装两条分页；单次滑动最多再展示两条，末批不足两条时显示剩余内容。

## 模块编号

清单 schemaVersion 仍为1，新增可选 `number`，格式为完整拼音（每字后接声调数字）-App版本-罗马数字小编号。

| 模块 | 首次制品编号示例 |
| --- | --- |
| 官方主题库 | `guan_1_fang_1_zhu_3_ti_2_ku_4-0.2.29-I` |
| 高级个性化 | `gao_1_ji_2_ge_4_xing_4_hua_4-0.2.29-I` |
| 手机便捷管理 | `shou_3_ji_1_bian_4_jie_2_guan_3_li_3-0.2.29-I` |
| 分层猫娘素材 | `fen_1_ceng_2_mao_1_niang_2_su_4_cai_2-0.2.29-I` |

`create_module_assets.py --module-build I` 默认生成 I。II、III、IV 等表示同一 App 版本内的制品小编号，只允许标准大写罗马数字（I～MMMCMXCIX）。已公开 Tag 和附件保持不可变；小编号不能作为覆盖已发布附件的理由。

编号是展示信息，`revision` 仍是独立内容摘要。模块安装目录、稳定ID、下载文件名、签名及主包兼容版本保持原规则。即使新清单编号包含新的 App 版本，只要资源真实内容没变，仍复用本机经过签名与完整性检查的旧包；显示本机实际保留包的原编号。原生分包必须配套主包版本。旧清单没有 `number` 时继续可读，显示内容标识，不虚构旧编号。

## Gitee 诊断与手动同步

2026-11-15 匿名探测结果：

- `https://gitee.com/api/v5/repos/MJJ13445/ACM-Forever/releases?per_page=10`：HTTP 200，空列表 `[]`。
- `https://gitee.com/api/v5/repos/MJJ13445/ACM-Forever/releases/latest`：HTTP 404。
- `https://gitee.com/MJJ13445/ACM-Forever/releases/download/v0.2.28/update.json`：HTTP 404。

这些结果说明探测时没有可读的 Gitee Release；不代表所有手机网络均已验收。App 默认确实是 Gitee 优先，然后尝试 GitHub。源码手动同步不会生成 Release 或同步附件。若两源都失败，更新页列出各自错误；命中 GitHub 时展示 Gitee 失败原因。App 版本结果不再等候模块清单网络请求，模块报告独立后台更新。

已手工指定地址的用户设置不擅自覆盖。在检查更新中清空“版本发布地址”即可恢复当前 Gitee 优先默认。Gitee 同步仍由维护者手动处理，本轮不上传 Gitee、配置令牌或部署服务器。

发布后需要把 GitHub Actions 生成的 APK、校验文件、四模块、`modules.json`、`update.json` 共8个附件放入 Gitee 同版本正式 Release。APK/模块字节与签名不改；JSON 的 APK 和模块URL须指向同版本 Gitee附件，不能直接上传仍指向GitHub的原清单。可复用 `gitee_release.mirror_files()` 离线准备这些文件，详见 [android-v0.2.27-gitee-updates.md（镜像说明）](android-v0.2.27-gitee-updates.md)。不使用第三方下载代理替代签名或摘要校验。
