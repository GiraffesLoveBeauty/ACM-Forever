## 用户行为

| 场景 | 本轮行为 |
| --- | --- |
| 管理员查看题单完成情况 | 默认“不排名”，可选“按完成数量排名”。先按身份、完成状态及关键词筛选全体成员，再按完成题数降序排列，最后分页；相同数量并列，例如 1、1、3，同分保持原接收人顺序。旋转保留选择。普通成员没有管理入口及权限。 |
| 旧服务器未提供排名 | 默认不排名照常使用；选择排名而响应未确认 `order=completed` 时显示无接口提示，不能把当前页冒充全体排名。 |
| 弱网下切页、返回 | 主页面和共用详情先绘制缓存或占位，独立调度读取；取消离开页面的读取订阅，忽略旧页面和旧账号结果。返回栈和滚动位置按原页面快照恢复。 |
| 提交后立即离开 | 写操作继续完成，界面不等网络结束；回调须核对页面、会话与草稿。不会自动重放发帖、评论、绑定、审核或注销。草稿保留恢复文本，提交前仍立即保存。 |
| 连接失败 | 读取失败后约 10、20、40、60 秒重试，带少量随机偏移、最长 60 秒；当前页恢复网络时提前重试，隐藏页面暂停轮询。保留 10 秒红色可关闭警告、关闭后继续重连、成功绿色提示 3 秒。缺失接口和权限错误不走连接重试。 |

## 减少传输的实现边界

- `ReadRequests` 按服务器、会话代次、完整路径和写入缓存代次合并正在进行的相同 GET，最多两条普通 JSON 读取并发。订阅者独立获得 JSON 副本；取消某页不会误取消仍被另一页使用的请求。取消连接在后台执行，不在 UI 线程调用可能阻塞的 `disconnect()`。
- `PageReads` 将缓存回放、页面网络读取和原有写队列分开。`ApiClient.stateLock` 只保护短时状态快照，不持有它等待网络；写事务仍串行。旧响应不得更新新账号 Cookie、CSRF、头像或触发退出。管理、认证和注销响应不用于页面缓存回放。
- `ReadInvalidation` 维护写入与读取的关联：点赞/评论只失效论坛、我的社区和相关通知，不清题库与榜单；草稿保存只失效草稿相关读取。认证变化清空全部会话缓存。写入增加缓存代次，写入前开始的旧 GET 不能覆盖写后缓存。
- 草稿停笔 2 秒后合并保存；提交前 `flush()`。不新增失败自动写重试。保存期间的继续输入仍归原草稿，切账号/草稿的迟到回调不覆盖新输入。
- HTTP 条件缓存仅用于公开能力清单及 Wiki，且服务器必须返回允许缓存的策略和 ETag；304 复用原文。内存验证记录最多 16 条、总计 2 Mi 字符，退出或切源清除。显式 `no-store` 不保留 HTTP 验证副本或图片复用副本。
- 原有账号隔离的短期页面快照仍在进程内存中用于“先展示、再刷新”，不属于新建的磁盘 HTTP 缓存；不能把它描述成永久缓存或离线授权。图片不另做有损压缩，PDF 与模块继续使用原有安全、大小和内容校验，模块是否更新仍按 `revision` 判断。

## 兼容后端改动

1. `GET /api/admin/training-tasks/<id>/progress` 新增可选 `order=none|completed`，响应增加 `order`，排名时每项增加 `rank`。默认保持原顺序；鉴权、筛选、固定任务分母及读站内证据行为不变，无数据库迁移。
2. 移动论坛 `/api/mobile/v1/forum/posts` 最小 `page_size` 从 5 改为 2，支持 App 真正每次只取两条；原 Web 接口最小 5、默认 12、上限 30 保持不变。能力清单增加 `forum_small_pages`、`training_progress_order`。
3. 公开能力接口新增内容 ETag/304；公开 Wiki 复用已有条件响应。仅公开能力和明确 `public` 的 Wiki JSON 对至少 1024 字节且压缩后更小的响应协商 gzip；尊重 `gzip;q=0`，增加 `Vary: Accept-Encoding`。不压缩含 Set-Cookie 的响应，不放宽私有接口 `no-store`，不修改 CSRF、权限、限流或 Cookie 策略。

`feat/api/**` 在合并 main 后会触发现有服务器部署。因此本 PR **合并前必须完成后端负责人联调和运维发布确认**。本轮不改 Nginx、服务器路径、密钥、发布工作流或自站更新源；Gitee 优先、GitHub 兜底和手动镜像保持现行安排。
