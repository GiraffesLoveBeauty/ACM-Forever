## 本地实测

使用 Windows 11、Python 3.12.14、SQLite 3.53.1，全部合成数据，不访问生产数据库或真实成员账号。

- 1,000 接收人 × 50 题，25,000 条合成 AC，生成 50,000 条进度记录。
- 本轮审核修复后重测：发布及聚合 2,480.49 ms；本地汇总 254.98 ms，汇总仅 1 次 SELECT。
- HTTP 进度分页第 1/25/50 页耗时 275.60/286.80/274.76 ms，每页 20 人，固定分母 1,000 人。
- 500 人全部完成，25,000 / 50,000 道成员题目完成。注销其中 30 人后分母仍为 1,000，匿名已确认成绩保留，异常人数 30。
- SQLite 在线备份与恢复 integrity_check=ok；重复迁移保留全部 50,000 条进度。
- 以上耗时为本机样本，不代表生产容量保证。

## 2026-11-11 审核修复

本轮修复审核提出的 3 项 P2，并将正式回归加入既有 tests/e2e：

- 草稿保存只提交独立快照。响应返回时保留期间的新输入，并继续标记为未保存；保存或预览等待期间发生修改时，不进入旧快照的发布确认。桌面和手机均验证二次保存、离开保护及服务端实际保存值。
- 发布时未绑定 CF 的接收人首次绑定后，GET 即时显示待同步，任务页可以发起刷新；无需等待预先聚合。API 回归验证 202 入队和后续改绑隔离，浏览器验证真实资料绑定和刷新按钮可用。
- 本地聚合、列表摘要与逐题详情共用核验规则。覆盖时间不足时即时计入待核验；完整覆盖周期的对照任务不会因时间推进失效。GET 不修改冻结证据或同步状态，不访问 CF，不创建同步任务，已确认 AC 成绩保留。

本轮未在 Windows 重跑后端全量；上表明确区分首轮全量与本轮 17 项定向回归。最新提交的完整 Linux 自动检查结果记录在对应 PR，本文件不把旧提交的检查视为新提交通过。所有本轮探针、临时数据库、性能样本、备份、构建及浏览器产物均保存在项目外。

## 发布准备

ACM_TRAINING_TASKS_ENABLED 默认 false。先由运维备份数据库及 WAL 一致性快照，部署兼容的新存储/API，再完成预生产权限、题库元数据、真实 CF 账号与同步覆盖验收，最后设置 true 并重启服务。开关关闭时成员首页不显示新入口，发布 API 返回 feature_disabled；历史查询和证据保留。所有前置 PR 合入期间保持开关关闭。

建议预生产用相同 1,000×50 样本确认：分页常规响应不超过 1 秒、发布事务不超过前端 15 秒超时；根据实际部署机器和并发负载调整，不能用本机测试代替运维确认。
