## 使用方式

- **题库**：平台、AC范围和收藏状态下增加关键词输入框及“题目标签”入口。支持题名、题号、标签关键词；关键词和选中的完整标签同时生效。顶部搜索栏继续搜索全站。
- **比赛进度**：沿用原有关键词框，增加完整题目标签筛选；与平台、已AC或收藏范围组合。
- **全局搜索**：启用题目或比赛进度模块且已登录时显示相应标签入口。两个模块各自选择，不改变用户、论坛、Wiki等其他模块的查询。
- **标签窗口**：从服务器读取真实原始标签，可在窗口中搜索候选；选择标签后关闭窗口并筛选。“全部标签”清除精确标签。重复点击不会叠加窗口，不提供虚构默认标签。

“dp”只匹配具有完整 `dp` 标签的题目，不因为存在 `digit dp` 就命中；大小写不影响完整标签匹配。标签候选窗口中的文字搜索则是候选名称的子串搜索，两者语义不同。原始标签不翻译、不拆词，也不拿二次处理的算法分类代替。

## 现有接口

| 用途 | 请求 | 参数与边界 |
| --- | --- | --- |
| 原始标签候选 | `GET /api/me/problems/tags?platform=…` | `tags`为字符串数组；平台可空或为CF、AtCoder、洛谷、牛客、校OJ的平台ID；需登录 |
| 题库筛选 | `GET /api/me/problems` | `tag=关键词`与`problem_tag=完整标签`独立编码，同时传平台、范围、收藏状态和分页 |
| 比赛进度筛选 | `GET /api/me/problems/tracker` | 同时传`tag`、`problem_tag`、平台、范围、收藏与分页；仍受已采集比赛目录限制 |

契约依据：[api.md](api.md)、`feat/api/acm_api/problem_tags.py`、`backend_api.py`和`problem_tracker.py`。后端在分页前组合条件并计算总数。`problem_tag`最多100个Unicode码点，`%`、`_`不作为通配符；空标签不附加该参数。关键词限制100个Unicode码点，避免截断代理对。选项格式异常、无权限或接口缺失按真实失败处理。

## 条件、缓存与页面关联

选标签、提交关键词或改变筛选范围回到第一页；翻页与原生题面返回保留条件。题库的已提交关键词、正在输入的内容、完整标签和页码参与页面栈/Activity状态保存；题库结果更新只替换结果容器，不重建关键词输入框。切换平台清除完整标签，保留关键词；题库“清除搜索与标签”不改变AC和收藏范围。比赛进度及全局搜索同样保存相应标签，切换账号清空标签并关闭旧窗口。

标签列表采用既有按服务地址和会话隔离的进程缓存：先回显真实缓存，再后台读取；短暂失败保留可用候选。原有403/404/410缓存失效规则继续执行，不能保证已失效接口仍有候选。窗口关闭、页面切换或账号代次变化后，丢弃迟到响应及旧点击回调。未持久化新增账号数据。

失败区分“无API接口”“无网络”“服务器异常”和有效空候选；错误不会因输入搜索词而变成“暂无标签”。网络请求超过10秒显示连接预警；用户触发且没有缓存的失败及时显示预警，沿用持续重试/手动关闭/恢复成功3秒提示。重试只执行读取；关闭标签窗口即停止其重试。
