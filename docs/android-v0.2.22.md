未登录时只显示登录界面：隐藏顶栏、搜索、底部栏目、设置和更新入口，不渲染公开论坛、榜单或题库。自动登录完成前停在等待页，登录失败回到表单；按返回键不会恢复其他内容。内部子 Activity 在启动、恢复及会话失效时校验登录状态，未登录将隐藏原窗口并清理任务栈回登录。更新检查和弹窗在登录后启动。

唯一未登录例外是用户确认保留的“查询注销结果”，仅在本机存在待确认的加密注销回执时可进入，仍只查询已有提交。回执清除后通知前台登录页更新入口，避免确认成功后留下失效按钮；没有回执的认证失效直接回登录，不保留旧业务页。

## 本轮检查与处理

- 更正旧注销测试的预期：明确拒绝认证且没有待确认回执时，按新要求回登录，而非继续在注销错误页浏览；仍验证不重发 POST、不误报成功及重新登录后的手动重试。
- 修复回执异步清除后登录页入口可能不及时消失的问题；回执存在性变化重新检查前台页面的登录资格，不执行解密、不等待网络锁、不重放注销。
- 171 项 JVM 单元测试通过，0 失败/错误/跳过；Debug 主包、测试包及 Lint 构建通过，Lint 0 错误、57 条既有警告。
- Python 发布/人员资源检查 40 项通过；官方主题资源检查 2 项通过。人员条目覆盖所有日志版本，头像的尺寸、PNG 内容、摘要和路径完整性均核验。

### PR #111 首轮评审修正

[Review 5804771612](https://github.com/GiraffesLoveBeauty/ACM-Forever/pull/111#pullrequestreview-5804771612) 针对 `d97612a` 提出一条 P2：注销 POST 返回 401 时，会话失效通知可能先于回执清除完成；第一次登录检查因回执仍在而放行，清除后又未检查当前注销页，导致未登录且无回执时仍停在错误页。

回执清除现在统一先删除本机回执，再通知登录门禁；确认结果和服务器明确拒绝提交均走同一入口。回执变更复用会话变更的前台检查，覆盖登录主页和当前注销子页；仍有回执的未登录用户继续仅查询既有回执，已登录用户不被误踢。

仪器测试在测试 APK 内包装会话回调，固定让第一次主线程登录检查在回执清除前完成，再验证后续无需旋转或恢复页面就回登录。该调度只存在于测试包，不向生产代码添加延时或测试开关。

修正后重新完成 Debug/测试包构建、171 项 JVM 测试和 Lint（0 错误、57 条既有警告），并在独立的新建 API35 模拟器上通过 `accountclosure`、`creditslogin`、`startupupdates` 三组回归。`accountclosure` 日志包含固定“先检查、后清除”顺序的检查点；先前参考设备断开未计作通过。本轮沿用 v0.2.22，不合并、不发布。

可复现方式：在 `Android_APP/app/` 执行 `testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest`；独立测试包 `ReaderSmoke` 使用 `-e mode creditslogin`、`accountclosure` 或 `startupupdates`。构建及模拟器使用保留 `.invalid` 域名的合成响应，禁止生产写入；主包不含测试夹具。具体命令与关联见维护规范。

## 保留的限制与发布范围

- 名单是 2026-11-07 的离线快照，之后新参与者在后续版本补录；机器人无意见不代表人工批准或完整真机验收。
- 少数旧版只有本地日志或草稿，没有公开 APK，本轮不补传、不移动旧 Tag，不伪造下载地址。
- v0.2.21 曾在 GitHub 刚创建草稿后的识别环节失败，原 Tag 重跑后成功。这里记录已观测到的发布可靠性问题，不修改发布校验或绕过 Actions；以后如修复需独立验证。
- 尚缺的社团训练等接口继续按既有真实状态显示，本轮未新增业务后端或数据库修改。客户端登录门禁不代替后端权限检查，网页原有公开访问不由此改变。
- 本次未修改 `feat/`、服务器配置或 `.github/` 工作流；自站发布 PR 和运维配置保持独立。未进行正式服务器或实体手机全量验收。
- 本轮没有发布新 APK；发布前仍需其他成员 review、适用 CI 和合并/Tag 确认。安装包、SDK、密钥、日志及测试截图不提交源码 Git。
