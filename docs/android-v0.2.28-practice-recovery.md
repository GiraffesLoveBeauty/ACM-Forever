# Android v0.2.28：练习、正式训练任务与模块恢复

状态：PR 候选，等待其他成员 Review；不代表已合并、已发布或生产服务器已部署。版本 `0.2.28 / code42`，基线 main `52d2878839540b07c823895b2adfc93c712ed43c`（v0.2.27）。本次不改 Web、业务后端、服务器部署工作流、自站待办或延期 1.0.0 双渠道。

## 页面与接口

- 底部“练习”（内部仍用 `problems`）依次显示装饰标题、训练工具、题库入口；`problem_bank` 子页才展开搜索、筛选、标签、收藏与分页。保留原页面栈、筛选与返回位置。
- “社团题单”就是管理员下发的正式训练任务。`TrainingTasksActivity` 使用 `GET /api/me/training-tasks?tab=active|upcoming|history` 和 `GET /api/me/training-tasks/{id}`。列表分页，详情展示发布人、说明、周期、两种 AC 规则、完成数、难度/标签、逐题证据与核验/同步时间，题目进入既有原生题面。任务详情独立打开，不销毁下方列表。
- “训练安排”页面标题为“我的训练安排”，取最近截止的 active；没有时取 upcoming；为空如实提示。移除旧打卡提交和 `/api/me/club/checkin` 请求，原有通知开关及时间保留在本地提醒设置。
- 详情刷新仅发送一次 `POST /api/me/training-tasks/{id}/refresh`，请求体 `{}`。queued/running 时每3秒 GET 详情，离开停止，返回重读。同步失败不重复写入，保留旧进度；429 显示服务端冷却时间，未绑定可进入本人 OJ 页面。
- `SearchModules` 中题单仍明确缺少“全量关键词搜索接口”，不会拿一页任务假装全量搜索。按题讨论、错题本、间隔复习依然缺正式接口。

## 手机便捷管理

“练习 → 训练工具 → 社团题单管理”仅在服务端重新确认 admin/root 后显示，复用 `admin` 可选模块；未下载仍先确认大小。便捷管理主页也有同一入口。所有管理页面重新可见时隐藏旧内容并重新核验会话，每次写入继续服务端鉴权和 CSRF，安装过 split 不构成授权。

### 题单

`AdminTrainingActivity` 接现成 `/api/admin/training-tasks`：

1. 任务与题目：标题、Markdown 说明，按行输入平台及标准题号，调用 `/resolve-problems`，展示逐行错误，服务端规范化/去重，最多50题。
2. 身份与周期：从 `/options` 读取真实业务身份及开放状态；输入北京时间，选择周期 AC / 历史 AC 规则，POST 新建或携带 `version` PATCH 草稿。
3. 发布确认：POST `/audience-preview`，分页核对接收人、排除原因及未绑定数量，显式确认排除后携带 `version`、`preview_token` 与 `Idempotency-Key` 发布。幂等键及对应草稿状态随 Activity 恢复保存，结果未知时保留键供用户主动重试；不自动重发。重新编辑或重新预览才换键，过期/并发变化由后端拒绝并提示重新预览。

题单详情可读操作记录、完成情况及逐人证据；按姓名/QQ、身份和完成状态筛选分页。草稿可删除；已发布任务仅延期/取消，原因必填并携带版本。首期仅 CF 能发布，其他平台按后端能力拒绝，客户端不伪造支持。

### 账号

`AdminAccountsActivity` 与成员资料分开：从现有 `/api/admin/web-accounts` 读取已开户账号，按关键词、学校、身份在返回范围筛选，再按20条分页。**现有账号接口一次返回全表，筛选是客户端执行，不宣称已有服务端分页。** 不增加开户、Excel 导入或采集功能。

- 仅当前页选择；批量临时密码限启用的普通成员，Root 另可逐项批量改角色。
- 每项携带列表读取时的 `expected_account_epoch`、`expected_credential_version`；旧单人改密、停用/启用和角色操作也使用完整账号快照，不用不含 credential_version 的成员资料替代。
- 冲突返回真实错误，结果未知不自动再改密；每项重新确认当前权限，失效停止后续队列。
- 结果仅在当前页面内存；不写 Bundle、偏好、日志或通用缓存。重复导出不再改密。Excel 只含成功取得的临时密码，所有单元格为文本，防止用户名被当公式执行。
- 用户主动“导出 Excel / 系统分享”才生成最小 XLSX，经未导出的、只读且临时授权的 `AccountExportProvider` 内存管道提供给系统分享。账号代次/权限变化或页面销毁时失效，授权最多10分钟。目标 QQ/微信等须支持系统文件分享；导出给外部应用后由用户管理副本。

## 独立模块编号与旧版兼容

清单仍为 `schemaVersion: 1`、四个模块和八个 Release 附件，增加可选字符串 `revision`。旧客户端忽略新增字段，仍取得与目标主包 code 相同的旧式配套模块；无需移动旧 Tag 或重写已公开附件。

| 制品 | 编号与复用 |
| --- | --- |
| 基础 APK | App code42，完整更新，固定包名/签名 |
| 官方主题库、分层猫娘素材 | `a1-` + 64位 SHA256；同内容跨 App code 复用原始签名归档 |
| 高级个性化、便捷管理 | `n1-` + 源码指纹；仍须目标 App code 的原生 split，不能复用旧 code 的安装文件 |

资源指纹只计算 `payload/` 中每个文件的相对路径、字节数和内容 SHA256，按路径排序，UTF-8 原文：

```text
ACM-MODULE-ASSETS/1\n
relative-path\0size\0sha256\n
```

ZIP 时间、签名及 App versionCode 不参与资源编号。新资源包的已签名 module.json 也含 revision，下载后比对真实资源指纹。`n1` 只表达功能源码修订，不能作为二进制可复用的凭据。

为兼容旧客户端，发布端**继续为每个 App code 生成四个配套附件**；新版在客户端跳过未变资源的网络下载，保留并验证本机原始签名包，再将解压内容暂存到目标 code。不会把重新签名后不同的 ZIP 当成原字节文件。本机 `.source-code` 指回原始签名归档，不能清理仍被引用的旧目录。未来 code 的资源不会在旧主包上提前生效。

旧包没有 revision 时，先验证大小/哈希、实际叶证书、已签名身份/API/code，再计算真实资源编号，不依赖“已下载”偏好猜测。没有本地清单时也可迁移孤立签名归档，但仍须验签及身份；篡改的本地归档不会因此变可信。

## 损坏恢复

`ModuleHealth` 在后台检查 acquired 模块和首次使用入口；`ModuleFiles.matches` 比较归档和安装目录真实字节，发现缺失、同大小变更、多余文件和链接等异常。完成标记只用于快速寻址，不能证明完整。

- 本机归档完整：staging 解压、校验后原子替换，失败回滚；修复无需联网。归档在而安装被中断/标记丢失，也可恢复。
- 归档不可用：已知损坏模块停用，保留用户设置及仍完整旧资源；显示修复原因。用户点击修复后，读取真实大小并确认“下载喵 / 点错了喵”，再走 Gitee 优先 / 同制品 GitHub 兜底。取消及网络失败可再次手动操作，不擅自联网无限修复。
- 原生模块依赖系统实际 split 状态；修复仍须系统确认安装。
- 更新页提供检查/本地恢复、真实状态、编号、修复/更新入口；有新版时显示目标编号和预计新增下载量，已缓存且验签完整的目标包不计下载量。保留“随 App 更新已下载模块”及默认开启，不下载未选模块。
- 修复后清猫娘资源内存缓存，不清本机背景、私人主题、账号密码、草稿或提醒，不重建正在编辑的页面。
