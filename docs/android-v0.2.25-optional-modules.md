# Android v0.2.25 可选模块与升级保留

状态：源码评审候选，本地验收已完成，提请其他成员 review；尚未合并、创建 Tag 或公开发布。基线为 v0.2.24 的 `4e98064f`，本轮版本 0.2.25 / code39。延期的 1.0.0 双渠道实现仍独立保留，本轮不纳入。

## 基础包和模块边界

基础包保留登录、论坛、题库、排行榜、个人中心、更新、简单配色/透明度、小剪影和加载提示。移动端便捷管理仍须由服务器鉴权，下载模块不是权限凭据。

| 模块 ID | 内容 | 实际制品 | 入口 |
| --- | --- | --- | --- |
| `official-themes` | 网页原 Vue/CSS/SVG 主题层、字体和许可证 | `module-official-themes.acmpack` | 个性化设置 → 主题选择 → 主题库 |
| `advanced` | 相册背景与裁剪、我的主题、保存/预览/重命名/删除、无损导入和分享界面 | `module-advanced.apk` | 个性化设置 → 高级个性化；图片/导入入口也会引导下载 |
| `admin` | 既有手机便捷管理 Activity | `module-admin.apk` | 账号设置的管理员入口，仅 admin/root 显示 |
| `cat-art` | 原彩色头像、加载插画、真实分层及换色掩码 | `module-cat-art.acmpack` | 个性化设置 → 分层猫娘素材 |

高级设置与管理员 Activity 使用 AGP dynamic-feature 真正从基础 DEX 拆出。Android 会提前初始化 ContentProvider，因此只读的 `ThemeShareProvider` 和共用主题/安全辅助类保留在基础包，分享界面仍只在高级模块。基础包不内嵌任何模块安装包或大幅分层素材。

未下载时先读取同版本的真实索引，再显示“此模块未下载，预计大小XXKB，是否下载？”，大小为实际制品字节向上取整到 KiB；“下载喵”和“点错了喵”等宽等高。取消不会下载制品，重复点击不会叠加弹窗。索引或文件不存在时显示真实失败，不用猜测大小或伪造下载成功。

资源包下载后校验、解压到 App 私有目录。原生功能包还须由 Android 系统确认安装；首次侧载需要允许安装未知应用，安装可能重启 App，未开启自动登录时可能需要重新登录，不会开启自动登录选项或删除用户数据。登录门禁、账号代次、管理员服务端校验继续生效。

## 已下载模块与 App 更新

检查更新页增加“随 App 更新已下载模块”，默认勾选，与“启动时自动检查更新”分别保存。

- 检查版本时同时读取该版本模块索引，单独显示模块检查结果。模块检查失败不伪造成功，也不隐藏 App 新版提示。
- 默认只更新用户已经下载的模块，不下载其他可选模块。
- 安装新版前，下载并验证这些模块；原生模块与基础 APK 在同一个系统安装事务中提交，避免版本不匹配。
- 资源包提前存入新版本目录，只在对应 App 版本安装后生效。取消 App 升级不会把新资源误应用到旧 App。
- 关闭选项后不下载新版模块，旧文件和设置继续保留。API1 资源包兼容时继续使用。Android 不允许旧 versionCode 的原生 split 随新基础包继续运行，因此这些原生模块须在新 App 中按需更新后才能使用；界面明确说明此限制。
- 关闭联动升级后，检查更新页会区分仍可使用的旧资源与当前版本的模块，并提供单个已下载模块的更新入口。手动补齐当前配套模块不会删除旧版本目录。
- 模块放在 `files/optional-modules/`，不属于“清理临时文件”或“清理已下载安装包”的范围。系统卸载 App 或用户清除全部应用数据仍会删除这些私有文件。

当前目录形式：

```text
files/optional-modules/{versionCode}/
  catalog.json
  downloads/module-{id}.apk 或 .acmpack
  installed/{resource-id}/payload原始内容
    .complete-api1
```

`optional_modules` 偏好中的 `acquired` 记录已下载的模块；`acmforever_settings.app_update_modules` 保存随 App 更新选项。保存的背景、裁剪、主题和账号仍使用原来的私有存储，不能改名丢失旧配置。

资源读取选择“不高于当前 App code、拥有 API1 完成标记”的最新已安装目录；未来版本暂存资源不能被旧 App 读取。原生可用性由实际安装的 `PackageInfo.splitNames` 确定，不能靠偏好标记解锁。

## 资源和签名契约

资源源文件移至 `Android_APP/module-resources/{id}/payload/`。官方主题渲染器工具和来源指纹同步使用该目录，继续使用网页原文件；WebView 无 App JS 桥、无业务 Cookie、无网络和文件系统访问权限。

`modules.json` 是同一版本 Release 的公开附件，schemaVersion 为 1，包括 versionCode、versionName 及完整的四个模块：id、kind、url、sha256、sizeBytes。`update.json.modulesUrl` 显式指向同版本索引，不从任意自定义清单偷偷回退其他源。当前客户端固定 GitHub 仓库与同版本附件路径，自站改动不在本轮。

下载流不携带业务 Cookie、密码或 CSRF；只接受 HTTPS 和受限的 GitHub 制品重定向。每个包最多 16 MiB，索引最多 64 KiB；读写有超时、取消、部分文件清理和大小限制。

除了整个包的大小和 SHA-256，还验证 JAR/v1 的实际签名叶证书与当前已安装 App 证书一致，以及签名覆盖的 id、API、versionCode、kind；不能用证书链中的其他证书替代签名者身份。原生包额外验证 splitName，最终由系统安装器再验签。拒绝 unsigned 条目、重复条目、路径穿越及过大展开体积。资源包只能读取私有目录中的对应资源，不能把下载索引当作执行任意代码的授权。

资源包签名内包含 `module.json`，原生 split 内包含 `assets/modules/{id}.json`。原生分包需要 v1 签名用于前置检验，并保留系统的 APK 签名校验。

## 构建与后续发布

```powershell
cd Android_APP/app
./gradlew --no-daemon testDebugUnitTest lintDebug :app:assembleDebug :advanced:assembleDebug :admin:assembleDebug :app:assembleDebugAndroidTest
```

`create_update_manifest.py` 先核实基础 APK；`create_module_assets.py` 从实际编译的 split APK、资源源目录及受控密钥生成四包、精确大小/摘要和索引。签名口令通过环境变量传入，不进入源码或日志。

将来按现有规则：本地完成 → 源码 PR → 别人 review → 获授权后合并 → 新版本 Tag 触发 Actions 构建、打包并发布。同一事务有八个附件：基础 APK、其 SHA-256 文件、update.json、modules.json、四个模块包。所有附件回下载逐一校验后才公开 Release；缺文件、大小/哈希不符或回读失败均保留草稿。已公开 Tag 和附件不可改写。APK 和模块制品都不提交源码 Git。

本轮没有修改网页、业务 API、数据库、Nginx、自站路径或任何线上配置。GitHub 下载速度仍受设备网络影响。

## PR #114 本地 review 修复

2026-11-09 的独立本地 review 审查 `efdeea9973`，指出一项 P2：已经安装便捷管理模块时，连续点击入口会重复启动标准模式的管理 Activity。原实现的 `returnFromAdmin` 检查和赋值在拆包时遗漏，模块索引读取用的 `pending` 无法覆盖已安装模块的直接启动。

修复保留原来主页的防重与返回刷新行为，由 `OptionalModules` 在管理页或下载页成功启动后回调设置 `returnFromAdmin`，主页恢复时释放并刷新。仅显示下载确认或取消时不设置此标志；启动抛出异常时显示错误且不占用防重状态；确认按钮在关闭后忽略迟到的再次点击。

新增独立仪器模式 `modules-admin-entry` 与 `modules-admin-consent`，使用真实已安装 split 和隔离测试会话。相同的连续点击用例在原审查版本基础 APK 上失败，确认能捕捉重复启动；修复版通过以下检查：

- 同一个 UI 任务内触发两次主页入口，仅产生一次真实管理 Activity 启动。
- 返回主页释放防重状态，之后可再次打开管理页。
- 模拟启动失败，不锁住入口，关闭错误提示后可成功重试。
- 首次未下载模块的确认可连续取消、重新打开，不下载制品，也不锁住管理入口。

本次重新运行 Java 单测，197项通过、1项 Windows 符号链接用例跳过；Lint、基础包/两个分包/仪器包编译、本地签名与制品审计，以及基础模块下载、真实分包系统确认安装、普通成员/管理员权限回归均通过。原候选的升级保留和其他页面回归仍见上文记录；新增修复须按新 head 复审，不能把原版本 review 视为新提交已获批准。
