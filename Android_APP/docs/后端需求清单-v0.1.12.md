## 二、现有排行榜增加两个可选参数

接口：`GET /api/community/leaderboard`。

- [ ] `period=today`：按北京时间当天 00:00（包含）至次日 00:00（不包含）统计；覆盖 `days` 的滚动窗口。不是最近 24 小时。未知非空 period 返回 400。
- [ ] `positive_only=1`：排除所选平台合计通过数为 0 的成员，先过滤，再计算总人数和分页。
- [ ] 保留平台筛选 `platforms`、排序 `sort`、搜索 `search`、页码 `page` 和每页数量 `page_size`。
- [ ] `page_size` 支持 5–100；App 提供 5、10、20、100 四档。
- [ ] 非整数、小于 1 或超过总页数的页码返回第一页；空榜按一页处理。
- [ ] 未传新参数时保留网页原有统计和过滤行为。

响应保留 `rows/total/page/page_size/days/sort/search/platforms`，补充以下字段：

| 字段 | 类型与含义 |
| --- | --- |
| `period` | 当日为 `"today"`；普通周期为空字符串 |
| `timezone` | 当日为 `"Asia/Shanghai"`；普通周期为 null |
| `positive_only` | 布尔值，表示是否在服务端过滤零 AC |
| `start_time` | 当日开始边界，Unix 秒；普通周期为 null |
| `end_time` | 当日结束边界，Unix 秒；普通周期为 null |

同一统计能力也由下文的移动端排行榜复用。App 会校验当日周期和时区字段；旧服务忽略参数时显示“无API接口”，避免把近 7 日数据当作当日数据。

## 三、公开成员身份和主页接口

以下路径统一加前缀 **`/api/mobile/v1`**，共七个路径、八项操作。

| 核对 | 方法 | 路径 | 用途及返回要求 |
| --- | --- | --- | --- |
| [ ] | GET | `/capabilities` | 返回 `api_version: 1` 和 `features` 能力对象 |
| [ ] | GET | `/leaderboard` | 复用原排行榜查询及新增可选参数，每行增加稳定的 `public_member_id`，用于跳转成员主页 |
| [ ] | GET | `/forum/posts` | 复用话题列表，每条增加 `author_public_member_id`；保留 `q/category/sort/page/page_size` |
| [ ] | GET | `/forum/posts/{id}` | 复用公开话题详情；帖子和评论增加 `author_public_member_id` |
| [ ] | GET | `/members/{public_member_id}` | 返回该成员的公开资料、座右铭和各平台生涯通过题数 |
| [ ] | GET | `/members/{public_member_id}/posts` | 返回该成员已发布的话题，支持筛选及分页，返回 `rows/total/page/page_size` |
| [ ] | GET | `/me/public-profile` | 返回当前登录成员的公开资料、稳定 ID 和座右铭 |
| [ ] | PUT | `/me/public-profile` | 只允许修改当前登录成员自己的座右铭 |

### 3.1 能力字段

`features` 包含以下布尔字段：

- [ ] `public_member_ids`：列表与详情提供稳定公开成员 ID。
- [ ] `member_profiles`：成员公开资料可用。
- [ ] `member_posts`：指定成员的已发布话题可用。
- [ ] `own_public_profile`：本人公开资料读取可用。
- [ ] `edit_motto`：座右铭编辑可用。

### 3.2 公开资料字段

| 字段 | 要求 |
| --- | --- |
| `public_member_id` | 随机生成、稳定的 32 字符公开标识；不是 QQ 或登录凭据 |
| `name` | 公开昵称 |
| `avatar_url` | 头像地址 |
| `status` | 公开身份 |
| `motto` | 座右铭字符串，未设置时为空字符串 |
| `platform_counts` | 对象，键为 `codeforces/luogu/atcoder/nowcoder/cjlu`，值为各平台生涯通过题数 |
| `total_count` | 五个平台通过题数合计 |

各平台通过题数按本平台题目 ID 去重。当前实现同时保留 `cf_count/luogu_count/atcoder_count/nowcoder_count/cjlu_count` 统计别名。

### 3.3 权限与数据边界

- [ ] 公开接口不返回 QQ、私有 OJ 绑定、逐题记录、收藏、草稿或未发布内容。
- [ ] 本人接口沿用现有登录 Cookie；PUT 请求校验 `X-CSRF-Token`。
- [ ] PUT 正文只接受 `{"motto":"内容"}`，拒绝额外字段和非字符串值。
- [ ] 座右铭去首尾空白后最多 100 个 Unicode 字符；空字符串表示清除。
- [ ] 只能编辑当前登录成员本人，公开成员路径不开放修改。
- [ ] 沿用现有会话校验：未登录或失效为 401，CSRF 失败为 403，首次改密要求为 428。
- [ ] 指定成员或话题不存在时返回 404；客户端需要区分内容不存在和整项能力未部署。
- [ ] 不通过昵称或头像推测成员身份，不将排行榜区间数量当作生涯通过数。

### 3.4 数据库初始化

- [ ] 新增 `mobile_public_profiles` 附加表，存放随机公开 ID 和座右铭，复用现有用户关联。
- [ ] 通过既有数据库初始化流程幂等创建，为已有成员及后续新成员补齐公开 ID。
- [ ] 重复初始化保留已经分配的 ID 和座右铭，不重置已有成员或做题数据。
- [ ] 发布前备份实际 SQLite 数据库及 WAL 状态，并验证旧数据库增量初始化。
- [ ] 回退代码时保留附加表及公开 ID 映射，避免重新发布后成员公开身份变化。

### 4.1 版本清单字段

| 字段 | 类型 | 要求 |
| --- | --- | --- |
| `packageName` | 字符串 | 固定为 `com.giraffeslovebeauty.acmforever` |

| `apkUrl` | HTTPS URL | 对应新安装包的可访问下载地址 |
| `sha256` | 字符串 | 对应 APK 的 64 位十六进制 SHA-256 |
| `notes` | 字符串，可选 | 更新说明 |

### 4.2 安装与签名约束

### 部署边界

现有 `sync-feat-to-server.yml` 在向 main 推送且变更命中 `feat/**` 等触发路径时同步服务器；仅推送主题分支不触发同步。本次 PR 包含 `feat/api/` 改动，合入 main 会触发同步，因此备份和运维发布确认应在合并前完成。

App 当前默认使用 Tailscale HTTPS 入口。手机需要该内网访问权限；新增 API 不会自动提供公网访问。
