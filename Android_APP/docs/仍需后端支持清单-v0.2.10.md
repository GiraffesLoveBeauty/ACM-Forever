## 第一优先级：安装包发布（App 专属）

App 已有手动检查、启动自动检查选项、仅 Wi-Fi 自动下载选项、下载进度/取消及恢复跟踪；安装前校验包名、版本、SHA-256、Android 兼容性和已安装签名。Android 系统仍要求用户确认安装。

服务器尚缺：

- `GET /api/mobile/v1/releases/latest?channel=debug|release`：公开只读最新版清单。
- `GET /api/mobile/v1/releases/files/<channel>/<version>/<filename>`：拟新增的 APK 下载路径，支持 HEAD/Range。
- 清单字段：`packageName`、`versionCode`、`versionName`、`apkUrl`、`sha256`、`sizeBytes`、`minSdk`、`notes`。哈希和大小取自实际 APK。

建议后端修改：新增 `feat/api/acm_api/release_api.py` 与相关测试；在最新 `feat/api/app.py` 注册、配置持久化目录并复用已有 `PUBLIC_BASE_URL`；更新 `docs/api.md`、`feat/api/README.md`。无需新增数据库表或让 App 直连数据库。这些均尚未实施，执行涉及 Android_APP 外文件，仍需确认范围。

建议上传位置与顺序：

1. 源码/测试/文档提交到 GitHub `GiraffesLoveBeauty/ACM-Forever` 的新版本分支，拟名 `feat/android-v0.2.10-release`，建 PR。只挑必要改动，不使用 `git add .` 混入历史工作树草稿。
2. 合并前跑后端测试并备份部署；main 上命中 `feat/**` 的改动会触发现有服务器同步，主题分支 push 不会。
3. 仓库工作流配置为 `WYJ@100.91.79.54:22`，代码部署目录 `/home/WYJ/acm-forever-feat`。这是仓库配置，未在本轮实测账号权限。
4. APK 及清单建议用 SSH/SCP 存到拟新增的持久化目录 `/home/WYJ/acm-forever-data/mobile-releases/debug/`，版本 APK 放 `0.2.10/acmforever-0.2.10-debug.apk`，当前渠道清单放 `latest.json`。不要放在每次被替换的代码目录。
5. 先上传临时 APK，远端校验真实哈希和大小，再发布文件，最后原子替换 `latest.json`。release 独立渠道；签名密钥不入 Git 或下载目录。

## 第二优先级：其他缺失接口

“网页有基础”表示有相关组件，并不表示网页已经实现 App 提出的完整功能。

| 能力 | 归属、网页已完成部分 | 仍缺什么 |
| --- | --- | --- |
| 公开成员标识 | 网页有论坛作者和排行榜成员展示 | 稳定公开 ID；不能用昵称或公开 QQ 代替 |
| 他人公开主页 | 网页有本人资料、平台题数和本人最近 AC | 他人公开资料、各平台累计题数、按作者查询已发布话题；不公开逐题记录 |
| 社团题单 | App 扩展需求；网页有今日训练生成和历史 | 教练创建下发、分配、截止时间及完成进度 |
| 按题讨论与标签 | App 扩展需求；网页有泛论坛、评论、审核和举报 | 帖子与“平台＋题号”的关联、讨论标签和精确查询 |
| 私人错题笔记 | App 扩展需求；网页有题目收藏 | 私人错因、笔记和标签；最新 `_save_problem_favorite` 对 `note_md` 返回 410，不能用现成笔记接口补齐 |
| 间隔复习进度 | App 扩展需求；网页有赛事六态复盘 | 个人复习阶段、到期时间、1/3/7 天推进与今日训练联动；旧 study-plan/review 路由已退休 |
| 每日目标与打卡 | App 扩展需求；网页有训练汇总、活跃日期、连续天数 | 目标、达标状态和幂等打卡写入；本机通知无需新增接口 |

座右铭已从本版客户端及当前需求移除。本人资料、平台题数、本人话题、收藏、云端多草稿、图片、通知、Wiki、排行榜及题面/PDF 继续复用已有接口，不在缺失需求中重复列出。本机主题、裁剪、透明度、主题预览和页面返回栈不需要后端。
