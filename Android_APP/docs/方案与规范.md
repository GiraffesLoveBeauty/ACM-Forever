# ACM Forever 安卓客户端方案与规范整理

## 0.1.12 本轮实现

全局弹窗协调器：同一 Activity/浏览器文档仅保留一个弹窗，重复打开同一窗口保留编辑，异步弹窗入口防重、已有弹窗阻止底层排队点击，合法后续确认关闭旧弹窗再打开。

排行榜新增北京时间当日区间，按所选平台过滤总 AC 为 0 的成员；上一页 → 第（可输入页码）页（共X页）→ 一页5/10/20/100项 → 下一页。非法或越界输入回第一页，切换筛选/数量回第一页；空榜共1页。旧服务器普通区间先读齐公开分页再过滤，缺少当日周期确认时显示无API接口。

顶部搜索 → 搜索页（最近 10 条可点击历史方框）→ 提交后结果页；提供历史记录单条删除、历史设置停用记录与清空。历史只在本机保存，无默认词条。

登录增加记住账号与自动登录。原生通过 Android Keystore 的 AES-GCM 密钥加密会话 Cookie，服务地址作为附加认证数据；最长 30 日且不超过服务器 Cookie 期限。每次启动请求既有 `/api/auth/me` 验证后才进入登录状态，过期回登录；网络失败显示真实错误。退出、关闭自动登录或切换服务器时删除会话，CSRF 不落盘；另行勾选“保存密码”后用 Keystore AES-GCM 加密保存密码，绑定服务地址与账号，退出/改密/取消保存时清除，应用禁止备份。浏览器账号和选项保存在本机，密码交浏览器密码管理器（不支持时禁用），不能绕过 HttpOnly 或跨域策略。首次使用需手动登录并勾选。

本人各平台通过题数来自 `/api/me/profile` 顶层统计；已发布话题从 `/api/forum/mine/posts` 筛出 published，受原接口最近 100 条限制。两区独立报错，座右铭接口缺失只影响座右铭。他人主页仍需要稳定公开 ID 接口。顶部工具使用矢量加号，漏斗对已打开和请求中的状态防重入。

## 一、已核实的仓库约束

1. `ACM-Forever` 是工程代码仓库，前期需求讨论在 `CJLUACM-DLC`。新功能从 `main` 建短期主题分支，通过 PR、跨人评审及适用的自动检查合入；不直接推送或强推 `main`。提交、推送、合并按用户要求执行。
2. 一个 PR 解决一个连贯问题；源码、验证和使用说明一起交付。接口、配置或使用方式改变时同步文档。只暂存本任务文件，不提交凭据、生产数据、缓存和真实学生信息。
3. Web、机器人和后续移动端经统一平台 API 使用数据；数据库访问留在后端。`/internal/v1/*` 的 Bot Token 只能保存在受控服务端，不能放进 App。移动端可使用公开读取接口及有权限的 `/api/*` Web 会话接口。
4. `feat/**` 合入 `main` 后会自动同步到服务器。本次后端与 API 文档修改已经获得用户授权，但合并和生产部署仍需另行批准；网页源码和部署工作流未改。
5. 当前页面实现的普通成员主入口是论坛、排行榜、个人中心。网页中的复习队列、提交时间线和学习工作区已下线，不纳入 App 首页。论坛和排行榜有手机样式；App 样品沿用其信息架构与薄荷绿、深绿、黄绿配色，不改网页文件。

## 二、产品设计

**定位。** 应用中文名“打一辈子爱臭美”，英文名“ACMforever”，面向计量 ACMer 的随身学习社区。首屏优先让学生找到话题、查看公开排名与题库。结构参考哔哩哔哩等成熟手机社区 App 的“公开个人主页 + 独立账号设置”信息层级；内容在中部滚动，底部五个入口单手切换，顶部放头像、搜索与常用工具小“＋”，底部中央“＋”直达发帖编辑。沿用现有网页业务语言与配色，不搬用第三方品牌图形或资源。

**导航目录。** 顶部头像直接进入账号设置，搜索按当前栏目检索，右上角小“＋”只放扫一扫和检查更新。底部固定为“主页（论坛）｜排名｜＋｜题库｜个人中心”；个人中心是他人可看的公开主页，底部“＋”进入发帖编辑。论坛“社区话题”标题右侧的漏斗按钮统一设置分类与排序。普通网页二维码编码完整 `https://` 链接；打开前展示域名与完整链接，确认后在 App 内浏览页打开。相机识别和官方站内跳转规则仍待确认。

### 手机社区界面的参考与取舍

参考哔哩哔哩等手机内容社区的常见信息层级，按本项目业务落地如下。已读取 [哔哩哔哩官方客户端介绍与下载页](https://app.bilibili.com/)；该页用于核实官方发布入口，不能证明最新版手机端每个按钮的位置。本轮没有实机操作最新版哔哩哔哩客户端，因此以下是设计参考与实现决策。

| 界面层级 | 本 App 的具体设置 |
| --- | --- |
| 公开个人主页 | 顶部头像、用户名、身份和座右铭，下面是五个平台与合计的统计卡片，再显示已发布论坛话题 |

**管理员入口。** `/api/auth/me` 返回的真实 `role` 决定管理员栏，未登录与普通成员均隐藏；进入管理中心再次验证。管理员没有成员资料时仍保留管理与账号安全入口。`Android_APP/admin-console` 只读复用九个现有 Vue 模块并打包进 APK，通过 ApiClient 使用同一会话和 CSRF，无需再次网页登录。Root 控件及权限沿用后端校验。原生桥只在打包资源可用，限制管理请求路径、方法、体积和队列，拒绝远程页面和外部地址；外链确认后在独立无管理桥的浏览页打开。CSV/主题导出使用系统文档选择器，主题导入、剪贴板和临时账密离开提醒保留。模块接口缺失/断网显示占位错误面板，不展示虚假管理数据。

论坛与排名列表分页字段沿用既有契约，公开响应不含私密 QQ/真实姓名/学校；没有稳定公开 ID 时不能按昵称推断身份。本人题库、训练、收藏、草稿及赛事状态均用服务端会话限定身份，客户端不发送他人所有者 ID。“我的话题”包含审核内容，不用于他人公开主页。CSRF 不持久化；账号密码仅在用户选择“保存密码”后以 Keystore AES-GCM 密文保存；自动登录会话由 Android Keystore 加密保存并在启动时联网验证；所有写入携带 `X-CSRF-Token`。头像限 PNG/JPEG/WebP、2 MB，服务端校验尺寸与内容。论坛 Markdown 和采集题面由本地 DOMPurify 白名单处理，公式使用不信任模式；阅读器无 App JS 桥，仅允许 HTTPS 图片和确认后打开的 HTTPS 外链，附带开源许可证。

**状态设计。** 每个数据页面都有加载、空列表、接口失败、未登录和刷新入口。网络失败时不把旧数据冒充实时结果；客户端不展示任何合成成员、题目、帖子或计数；错误方框替代对应数据区域并保留高度，部分请求失败不清除其他成功响应。窄屏按钮保持可触摸尺寸，正文可放大，颜色对比需在真机检查。

## 四、安装后更新

1. 用户在“顶部小＋ → 检查更新”主动检查内置的 HTTPS 版本清单（保留有效旧配置），账号设置也提供同一入口；无发布接口时显示红色“无API接口”，断网显示“无网络”。读取成功且版本不高于本机时显示“已是最新版”；检查进行中阻止重复请求。默认清单为 GitHub Releases 的固定 `releases/latest/download/update.json` 地址，客户端只跟随仍为 HTTPS 的重定向。清单至少包含 `packageName`、`versionCode`、`versionName`、`apkUrl`、`sha256` 和更新说明。自动启动检查可在正式地址和频率确定后加入。
2. 只有同包名且 `versionCode` 大于当前版本才显示“发现新版本”。用户点“更新X.X版本”后由 Android `DownloadManager` 下载；系统通知显示下载状态，不在后台静默安装。
3. 下载结束后复制到私有缓存并计算 SHA-256，核对真实包名、versionCode 及签名；只给系统安装器临时只读访问已核验文件。核验通过再启动安装器；Android 8 及以上首次侧载时，需要用户为本 App 允许安装未知应用。安装器会校验 APK 签名是否与已安装版本一致。
4. 包名和签名证书从首次正式发布起保持不变；每次发布递增 `versionCode`。用户选择先体验调试包、正式发布时卸载并重装。正式 Release 发布时，`.github/workflows/android-release.yml` 使用 Actions secrets 中的签名密钥构建 APK，校验包名与版本，计算哈希并附加 APK 和清单。所需 secrets 为 `ANDROID_RELEASE_KEYSTORE_BASE64`、`ANDROID_RELEASE_KEY_ALIAS`、`ANDROID_RELEASE_KEYSTORE_PASSWORD`、`ANDROID_RELEASE_KEY_PASSWORD`；不配置时工作流会失败且不会上传文件。若将来通过 Google Play 分发，应改用 Play In-App Updates，不混用侧载方案。
5. API 返回的论坛与排行榜内容每次刷新即可更新，不需要更换 APK。原生功能或打包界面变化仍需下载新 APK；“应用内更新”表示从 App 发起下载与安装，不代表绕过安卓系统安装确认。
