## 用户已确定的可见范围

- 公开：社区头像、用户名、身份、座右铭、各平台通过题数、已经发布的论坛话题。
- 不公开：逐题名称与通过时间、QQ 号、真实姓名、学校、OJ 绑定标识、收藏、草稿、待审核及未通过的帖子。
- 账号设置中的本人最近 AC 仍使用现有 `GET /api/me/profile`，与公开主页数据分开。

## 当前接口与缺口

| 现有接口 | 可用信息 | 缺口 |
| --- | --- | --- |
| `GET /api/community/leaderboard` | 公开昵称、头像、身份、五个平台通过题数和汇总 | 没有稳定公开成员 ID；不能可靠跳转到某人主页 |
| `GET /api/forum/posts`、`GET /api/forum/posts/<id>` | 已发布帖子、作者昵称和头像 | 没有稳定公开作者 ID；不能按成员查询 |
| `GET /api/me/profile` | 本人资料、统计、最近 AC | 需要登录，含本人资料，不能代替他人公开主页 |
| `GET /api/forum/mine/posts` | 本人所有非删除帖子及审核状态 | 含待审核内容，不能公开 |

## 建议的新接口

1. 为成员建立不含 QQ 信息的稳定、不易枚举的 `public_member_id`。在公开排行榜和公开帖子作者字段中增加此 ID。旧字段保持兼容。
2. `GET /api/community/members/<public_member_id>`：无需登录，仅返回头像、用户名、身份、座右铭、五个平台通过题数和汇总。通过题数按当前公开排行榜“生涯”口径去重，以 `platform_counts` 的平台键返回，`total_count` 是跨平台去重题数之和；排行榜现有的 `cf_count` 等字段保持兼容。禁止返回逐题数组。成员不存在或不允许公开时返回 404。
3. `GET /api/community/members/<public_member_id>/posts?page=1&page_size=20`：无需登录，只查询 `status='published'` 的帖子；返回 `rows/total/page/page_size`。列表沿用公开帖子摘要字段，分页参数和上限与论坛保持一致。
4. `GET /api/me/public-profile`：当前登录成员读取自己的公开主页信息，响应与公开资料接口一致，包含稳定的 `public_member_id`，供底部“个人中心”准确定位自己。登录失效返回 401，不通过昵称匹配排行榜。
5. `PUT /api/me/public-profile`：当前登录成员使用 CSRF 修改座右铭。建议只允许字符串，去首尾空白，长度上限 100 个 Unicode 字符；空字符串表示清除。昵称仍走现有 `PUT /api/me/profile`，头像仍走 `POST/DELETE /api/me/avatar`。

公开用户名语义需统一：当前排行榜会优先展示 Codeforces handle，论坛展示成员昵称。新主页建议固定使用社区昵称，同时保留现有排行榜字段，另增 `display_name` 与 `public_member_id` 以保持兼容。

建议的公开资料响应：

```json
{
  "public_member_id": "opaque-public-id",
  "name": "示例成员",
  "avatar_url": "/uploads/avatars/example.webp",
  "status": "成员",
  "motto": "每天进步一点点",
  "platform_counts": {
    "codeforces": 12,
    "luogu": 8,
    "nowcoder": 3,
    "atcoder": 4,
    "cjlu": 2
  },
  "total_count": 29
}
```

## 客户端接入次序

先在排行榜与论坛作者头像加入 `public_member_id` 跳转，再接公开资料、自己的公开资料和已发布帖子列表，最后开放座右铭编辑。任何返回缺字段、404 或网络失败都显示明确状态，不用昵称搜索结果猜测成员身份。当前 App 不提供演示数据和接口记录；缺失接口的内容区域显示红色“无API接口”，断网、超时、数据格式错误和内容不存在分别提示。原列表已有的真实公开姓名与头像可保留，但不以排行榜区间数量代替公开主页的生涯统计。本人账号设置继续调用现有私有接口。

## 设计参考与验收

借鉴常见手机内容社区的层级：底部个人中心是可分享的个人主页，顶部头像进入自己的账号设置；公开主页用头像、昵称、简介、统计和内容列表，账号设置按资料、训练、社区、安全与连接分组。视觉仍使用本项目的配色和图标。验收时分别使用登录者、另一位成员与游客访问，确认三者看到的公开字段一致，且逐题记录、草稿和待审核帖子始终不泄漏。
